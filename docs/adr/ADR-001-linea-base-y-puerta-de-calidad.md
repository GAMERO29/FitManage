# ADR N.° 01 · Congelar la línea base LB-1 y exigir una puerta de calidad automática antes de evolucionar el MVP

| Campo | Contenido |
| --- | --- |
| Estado | Aceptado (30/10/2026) |
| Contexto | El MVP heredado de Ingeniería de Software I tiene un núcleo de dominio sano (complejidad promedio 1,89, 48 pruebas, 98 % de cobertura), pero solo existe una de las cuatro capas del DAD y la auditoría encontró diez ítems de deuda, siete de impacto alto. El código no estaba en control de versiones: el `.zip` de la FPI-12 se perdió y hubo que reconstruirlo. En este semestre se agregarán persistencia, interfaz web, seguridad y despliegue, y cada cambio puede romper reglas de dinero (RN-03 a RN-07) sin que nadie lo note. |
| Decisión | 1. El estado auditado se congela como línea base LB-1 (etiqueta Git `LB-1`, commit `a2a0f3a`). 2. Todo cambio entra a `main` por Pull Request revisado que cite el ítem de deuda (DT-xx) o la solicitud de cambio que atiende. 3. El flujo `Calidad` de GitHub Actions bloquea el Pull Request si falla alguna prueba, si la cobertura del dominio baja de 95 %, si aparece un bloque con complejidad ciclomática mayor que 10 o si ruff o bandit reportan hallazgos. 4. SonarCloud se conecta al mismo flujo para conservar el historial de métricas. 5. El prototipo HTML queda congelado como referencia de experiencia de usuario y no se usa como código base. |
| Consecuencias positivas | La evolución se mide contra cifras objetivas y no contra impresiones. La deuda deja de ser invisible: cada pago queda trazado del ítem al commit. Las reglas de negocio quedan protegidas por pruebas que se ejecutan solas en cada cambio. Se recupera la evidencia que se perdió con el `.zip`. |
| Consecuencias negativas | Cada cambio tarda algo más (revisión y espera del flujo, cerca de 1 minuto). Trabajando en solitario, la revisión del Pull Request la hace el mismo autor, así que se apoya en la lista de verificación y en las herramientas automáticas. Los umbrales pueden frenar un arreglo urgente: se acepta saltarlos solo registrando un nuevo ítem de deuda con su plan de pago. |
